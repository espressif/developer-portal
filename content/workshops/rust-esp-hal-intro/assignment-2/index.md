In this assignment, your board joins a shared "room" over Wi-Fi and MQTT. Every board in the room shows up on a [web page](https://hahihula.github.io/esp-hal-mqtt-rgb-demo/), and anyone in the room can change the color of its RGB LED from there.

You'll build it step by step, starting again from a project generated by `esp-generate`. Along the way you'll meet Embassy tasks, the `esp-radio` Wi-Fi driver, the `embassy-net` network stack, and the `rust-mqtt` client.

The Wi-Fi and MQTT parts follow the [Wi-Fi Connectivity](https://docs.espressif.com/projects/rust/no_std-training/application/wifi-connectivity.html) and [Publishing Data to an MQTT Broker](https://docs.espressif.com/projects/rust/no_std-training/application/publishing-data.html) chapters of the Embedded Rust Training. This page links to them wherever they explain something in more depth.

## How it works

```
 your board  ──MQTT over TCP──▶  broker.hivemq.com  ◀──MQTT over WebSocket──  web page
   (Wi-Fi)                         (public broker)                          (your browser)
```

[MQTT](https://mqtt.org/) is a publish/subscribe protocol. Clients don't talk to each other directly: they connect to a **broker**, **publish** messages to named **topics**, and **subscribe** to the topics they want to receive. Here, the board and the web page are both clients of a free public broker, so the workshop needs no server of its own.

All topics of a room live below `esp-hal-workshop/<room>/<board name>/`:

| Topic | Direction | Payload | Retained |
|-------|-----------|---------|----------|
| `status` | board → page | `online`, or `offline` when the board disappears | yes |
| `color` | board → page | the LED color, `#rrggbb` | yes |
| `set` | page → board | a new color, `#rrggbb` | no |

The board also listens on `esp-hal-workshop/<room>/all/set`, so the page can set every board in the room at once.

A **retained** message is kept by the broker and delivered to every client that subscribes later. That's how a web page opened after your board started still learns that the board is online and which color it shows.

{{< alert icon="circle-info" >}}
A public broker is public: anyone can read and send these messages. Don't publish anything private.
{{< /alert >}}

## 3. The LED, now async

Create `src/led.rs`:

```rust
//! The onboard RGB LED, owned by one task. Other tasks send it new colors.

use embassy_sync::{blocking_mutex::raw::CriticalSectionRawMutex, signal::Signal};
use esp_hal::Async;
use esp_hal_smartled::{RmtSmartLeds, buffer_size, color_order};
use log::warn;
use smart_leds::{RGB8, SmartLedsWriteAsync, gamma};

/// The LED driver: one WS2812 LED, async RMT channel.
pub type Led = RmtSmartLeds<'static, { buffer_size::<RGB8>(1) }, Async, RGB8, color_order::Grb>;

/// The newest color for the LED. A `Signal` keeps only the latest value, so a
/// burst of colors from the web page never queues up.
pub static LED_COLOR: Signal<CriticalSectionRawMutex, RGB8> = Signal::new();

/// Waits for colors and writes each one to the LED.
#[embassy_executor::task]
pub async fn led_task(mut led: Led) {
    loop {
        let color = LED_COLOR.wait().await;
        // Gamma correction makes the LED look like the color picked on the web page.
        if let Err(e) = led.write(gamma([color].into_iter())).await {
            warn!("LED write failed: {e:?}");
        }
    }
}
```

- **One task owns the LED.** Other tasks never touch the driver. They send a color to `LED_COLOR`, and `led_task` writes it.
- **`Signal`** holds a single value. `signal()` stores a new value, overwriting one that wasn't read yet, and `wait()` sleeps until there is one. When the web page sends colors faster than the LED can show them, only the newest counts.
- **`#[embassy_executor::task]`** turns an `async fn` into a task that `main` can start with the spawner. A task's arguments must live forever (`'static`), because the task can outlive the function that started it.
- **Async RMT.** `led.write(...).await` hands the pulses to RMT and lets other tasks run until they are out.

## 4. The board's name

Every board needs a name in the room. Create `src/name.rs`:

```rust
//! A short, readable name for this board, made from its MAC address.

use core::fmt::Write;

use esp_hal::efuse::{InterfaceMacAddress, interface_mac_address};

const ANIMALS: [&str; 16] = [
    "bear", "wolf", "lynx", "seal", "crab", "frog", "duck", "goat", "hawk", "mole", "newt", "swan",
    "toad", "moth", "deer", "orca",
];

/// A 4-letter animal picked from the MAC address, then its last two bytes in
/// hex, for example `bear83e8`.
pub fn board_name() -> heapless::String<8> {
    let mac = interface_mac_address(InterfaceMacAddress::Station);
    let mac = mac.as_bytes();
    let animal = ANIMALS[usize::from(mac[3] ^ mac[4] ^ mac[5]) % ANIMALS.len()];
    let mut name = heapless::String::new();
    write!(name, "{animal}{:02x}{:02x}", mac[4], mac[5]).expect("4 + 4 characters fit");
    name
}
```

The name is made from the board's Wi-Fi MAC address, so nobody has to choose one, and it stays the same every time the board starts. It's the same recipe as in the ESP-NOW assignment, so your board has the same name in both.

## 5. Connect to Wi-Fi

Create `src/wifi.rs`:

```rust
//! Wi-Fi: keeps the station connected, and runs the network stack.

use embassy_net::Runner;
use embassy_time::{Duration, Timer};
use esp_radio::wifi::{
    AuthenticationMethodConfig, Config, Interface, WifiController, sta::StationConfig,
};
use log::{info, warn};

/// The Wi-Fi network, compiled in from the `SSID` and `PASSWORD` environment variables.
pub const SSID: &str = env!("SSID");
pub const PASSWORD: &str = match option_env!("PASSWORD") {
    Some(password) => password,
    None => "", // an open network
};

/// The station configuration for `SSID` and `PASSWORD`.
pub fn station_config() -> Config {
    let auth = if PASSWORD.is_empty() {
        AuthenticationMethodConfig::Open
    } else {
        AuthenticationMethodConfig::Wpa2Personal(PASSWORD.try_into().expect("password too long"))
    };
    Config::Station(
        StationConfig::default()
            .with_ssid(SSID.try_into().expect("SSID too long"))
            .with_authentication(auth),
    )
}

/// Connects to the access point, and connects again whenever the connection drops.
#[embassy_executor::task]
pub async fn connection_task(mut controller: WifiController<'static>) {
    loop {
        info!("Connecting to Wi-Fi '{SSID}'...");
        match controller.connect_async().await {
            Ok(_) => {
                info!("Wi-Fi connected");
                let _ = controller.wait_for_disconnect_async().await;
                warn!("Wi-Fi disconnected");
            }
            Err(e) => warn!("Wi-Fi connection failed: {e:?}"),
        }
        Timer::after(Duration::from_secs(5)).await;
    }
}

/// Runs the network stack: DHCP, DNS, TCP. It must run all the time.
#[embassy_executor::task]
pub async fn net_task(mut runner: Runner<'static, Interface>) {
    runner.run().await
}
```

- **`env!("SSID")`** reads the environment variable `SSID` when the firmware is **compiled** and puts its value into the firmware. If it isn't set, the build fails. You'll pass it on the command line in step 8.
- **`option_env!("PASSWORD")`** does the same, but gives `None` instead of failing when the variable isn't set. Leave `PASSWORD` out for an open network.
- **`connection_task`** owns the `WifiController`. It connects to the access point, waits until the connection drops, and connects again.
- **`net_task`** runs the `embassy-net` stack. The stack does DHCP, DNS, and TCP, but only while something keeps calling `runner.run()`.

Both loops never end, and both must keep running while the rest of the program works. That's what tasks are for: whenever one task waits, the executor runs another. For more on this, see [Why We Use Tasks](https://docs.espressif.com/projects/rust/no_std-training/application/wifi-connectivity.html#why-we-use-tasks) in the training.

**Compiling the Wi-Fi password into the firmware is a workshop-only shortcut.** Everyone who gets the firmware file can read the password out of it, and changing networks means rebuilding. Real devices get their Wi-Fi credentials at run time, for example from a phone. The [Wi-Fi Provisioning](https://docs.espressif.com/projects/rust/no_std-training/application/wifi-provisioning.html) chapter of the training shows how to do that with a captive portal.

## 6. Talk MQTT

Create `src/mqtt.rs`. It's the biggest file, so read through it before the walkthrough below:

```rust
//! MQTT: joins a room on the broker and lets the web page set the LED color.
//!
//! Topics, below `esp-hal-workshop/<room>/<board name>/`:
//!
//! | Topic    | Direction       | Payload                | Retained |
//! |----------|-----------------|------------------------|----------|
//! | `status` | board -> page   | `online` / `offline`   | yes      |
//! | `color`  | board -> page   | the LED color, `#rrggbb` | yes    |
//! | `set`    | page -> board   | a new color, `#rrggbb` | no       |
//!
//! The board also listens on `esp-hal-workshop/<room>/all/set`, which sets
//! every board in the room at once.

use core::{fmt::Write, num::NonZero};

use embassy_futures::select::{Either, select};
use embassy_net::{IpAddress, Stack, dns::DnsQueryType, tcp::TcpSocket};
use embassy_time::{Duration, Timer};
use log::{info, warn};
use rust_mqtt::{
    Bytes,
    buffer::AllocBuffer,
    client::{
        Client,
        event::Event,
        options::{
            ConnectOptions, PublicationOptions, SubscriptionOptions, TopicReference, WillOptions,
        },
    },
    config::KeepAlive,
    types::{MqttBinary, MqttString, TopicFilter, TopicName},
};
use smart_leds::RGB8;

use crate::led::LED_COLOR;

/// The broker, compiled in from `MQTT_HOST` and `MQTT_PORT` (optional).
const MQTT_HOST: &str = match option_env!("MQTT_HOST") {
    Some(host) => host,
    None => "broker.hivemq.com",
};
const MQTT_PORT: &str = match option_env!("MQTT_PORT") {
    Some(port) => port,
    None => "1883",
};
/// The room to join, compiled in from `ROOM` (optional).
pub const ROOM: &str = match option_env!("ROOM") {
    Some(room) => room,
    None => "lobby",
};
/// Every topic of this workshop starts with this.
const PREFIX: &str = "esp-hal-workshop";

/// How often the board pings the broker, so it knows the board is still there.
const PING_INTERVAL: Duration = Duration::from_secs(30);

type Topic = heapless::String<96>;

fn topic(name: &str, leaf: &str) -> Topic {
    let mut topic = Topic::new();
    write!(topic, "{PREFIX}/{ROOM}/{name}/{leaf}").expect("topic fits");
    topic
}

/// `#rrggbb` (or `rrggbb`) to a color.
fn parse_color(text: &[u8]) -> Option<RGB8> {
    let text = core::str::from_utf8(text).ok()?.trim();
    let hex = text.strip_prefix('#').unwrap_or(text);
    if hex.len() != 6 {
        return None;
    }
    let value = u32::from_str_radix(hex, 16).ok()?;
    Some(RGB8::new(
        (value >> 16) as u8,
        (value >> 8) as u8,
        value as u8,
    ))
}

fn format_color(color: RGB8) -> heapless::String<7> {
    let mut text = heapless::String::new();
    write!(text, "#{:02x}{:02x}{:02x}", color.r, color.g, color.b).expect("7 characters fit");
    text
}

/// Connects to the broker, and connects again whenever something fails.
#[embassy_executor::task]
pub async fn mqtt_task(stack: Stack<'static>, name: &'static str) {
    let mut rx_buffer = [0u8; 2048];
    let mut tx_buffer = [0u8; 2048];
    let mut color = RGB8::default();

    loop {
        stack.wait_config_up().await;
        if let Some(config) = stack.config_v4() {
            info!("Got IP address {}", config.address);
        }
        if let Err(e) = session(stack, name, &mut rx_buffer, &mut tx_buffer, &mut color).await {
            warn!("MQTT: {e}, reconnecting in 5 s");
        }
        Timer::after(Duration::from_secs(5)).await;
    }
}

/// One connection to the broker. Returns only when something fails.
async fn session(
    stack: Stack<'static>,
    name: &str,
    rx_buffer: &mut [u8],
    tx_buffer: &mut [u8],
    color: &mut RGB8,
) -> Result<(), &'static str> {
    // 1. Find the broker's IP address.
    let address = match MQTT_HOST.parse::<core::net::Ipv4Addr>() {
        Ok(ip) => IpAddress::Ipv4(ip),
        Err(_) => *stack
            .dns_query(MQTT_HOST, DnsQueryType::A)
            .await
            .map_err(|_| "DNS lookup failed")?
            .first()
            .ok_or("no address for the broker")?,
    };
    let port: u16 = MQTT_PORT.parse().map_err(|_| "MQTT_PORT is not a number")?;

    // 2. Open a TCP connection.
    let mut socket = TcpSocket::new(stack, rx_buffer, tx_buffer);
    socket.set_timeout(Some(Duration::from_secs(90)));
    info!("MQTT: connecting to {MQTT_HOST}:{port}...");
    socket
        .connect((address, port))
        .await
        .map_err(|_| "TCP connection failed")?;

    // 3. Connect MQTT. If the board disappears, the broker publishes the will:
    //    `offline` on our status topic.
    let status_topic = topic(name, "status");
    let color_topic = topic(name, "color");
    let set_topic = topic(name, "set");
    let all_set_topic = topic("all", "set");

    let mut client_id = heapless::String::<32>::new();
    write!(client_id, "esp-hal-{name}").expect("client ID fits");

    let mut buffer = AllocBuffer;
    let mut client = MqttClient::new(&mut buffer);
    let will = WillOptions::new(
        TopicName::new(MqttString::try_from(status_topic.as_str()).unwrap()).unwrap(),
        MqttBinary::try_from("offline").unwrap(),
    )
    .retain();
    let options = ConnectOptions::new()
        .clean_start()
        .keep_alive(KeepAlive::Seconds(NonZero::new(60).unwrap()))
        .will(will);
    client
        .connect(
            socket,
            &options,
            Some(MqttString::try_from(client_id.as_str()).unwrap()),
        )
        .await
        .map_err(|_| "MQTT connection refused")?;
    info!("MQTT: connected, room '{ROOM}', board '{name}'");

    // 4. Tell the room we are here, and which color we show.
    publish(&mut client, &status_topic, "online").await?;
    publish(&mut client, &color_topic, &format_color(*color)).await?;

    // 5. Listen for new colors.
    for filter in [&set_topic, &all_set_topic] {
        let filter = TopicFilter::new(MqttString::try_from(filter.as_str()).unwrap()).unwrap();
        client
            .subscribe(filter, &SubscriptionOptions::new())
            .await
            .map_err(|_| "subscribe failed")?;
    }

    // 6. Wait for messages; ping the broker when it's quiet.
    loop {
        let header = match select(client.poll_header(), Timer::after(PING_INTERVAL)).await {
            Either::First(header) => header.map_err(|_| "connection lost")?,
            Either::Second(()) => {
                client.ping().await.map_err(|_| "ping failed")?;
                continue;
            }
        };
        let event = client
            .poll_body(header)
            .await
            .map_err(|_| "connection lost")?;
        let Event::Publish(publish_event) = event else {
            continue;
        };
        match parse_color(&publish_event.message) {
            Some(new_color) => {
                *color = new_color;
                LED_COLOR.signal(new_color);
                let text = format_color(new_color);
                info!("MQTT: LED set to {text}");
                publish(&mut client, &color_topic, &text).await?;
            }
            None => warn!("MQTT: ignored a message that is not a #rrggbb color"),
        }
    }
}

/// The MQTT client type: a TCP socket underneath, buffers from the heap, and
/// small limits on how many requests may be in flight at once.
type MqttClient<'a, 's> = Client<'a, 's, TcpSocket<'s>, AllocBuffer, 2, 1, 1, 1, 0, 0, 0>;

/// Publishes a retained message, so the web page sees it even if it connects later.
async fn publish(
    client: &mut MqttClient<'_, '_>,
    topic: &str,
    payload: &str,
) -> Result<(), &'static str> {
    let topic = TopicName::new(MqttString::try_from(topic).unwrap()).unwrap();
    let options = PublicationOptions::new(TopicReference::Name(topic)).retain();
    client
        .publish(&options, Bytes::from(payload.as_bytes()))
        .await
        .map_err(|_| "publish failed")?;
    Ok(())
}
```

### Settings

`MQTT_HOST`, `MQTT_PORT`, and `ROOM` come from environment variables at build time too, but they are optional: `option_env!` returns `None` when a variable isn't set, and the `match` picks the default. Without any of them, the board joins room `lobby` on `broker.hivemq.com:1883`.

### Two loops

`mqtt_task` loops forever. Each round waits until the network stack has an IP address, logs it, and calls `session()`, which runs one connection to the broker and returns only when something fails: DNS, TCP, MQTT, or a lost connection. Then the task waits five seconds and starts over. All the error handling is the `?` operator plus this one retry loop.

### One session, step by step

1. **DNS.** The board looks up the broker's IP address. An IP address in `MQTT_HOST` skips the lookup.
2. **TCP.** `TcpSocket` opens a connection to the broker. The socket uses the two buffers from `mqtt_task` for the data in each direction.
3. **MQTT CONNECT.** The client sends its ID and a few options:
   - **Keep alive** of 60 seconds: the board promises to send something at least once a minute. If the broker hears nothing for 1.5 times that, it considers the board gone.
   - **Last will**: a message the broker publishes **for** the board when the board disappears without saying goodbye, for example when you unplug it. Here it's a retained `offline` on the board's `status` topic, so the web page greys the board out.
4. **Publish** `online` and the current color, both retained.
5. **Subscribe** to the board's own `set` topic and to the room's `all/set` topic.
6. **Wait** for messages. `select` waits for whichever comes first: the start of a packet from the broker, or the ping timer. If the timer wins, the board sends a ping, which keeps the connection alive when nobody is changing colors. If a packet comes, the board reads the rest of it, and if it's a color, hands it to the LED task and publishes it on the `color` topic.

`select` cancels the future that didn't win. That's only safe because `poll_header()` is **cancel-safe**: if it's cancelled halfway, the next call picks up where it left off. `poll_body()` isn't, which is why it is called only after the header has arrived. Each function's documentation tells you whether it's cancel-safe.

### The client type

```rust
type MqttClient<'a, 's> = Client<'a, 's, TcpSocket<'s>, AllocBuffer, 2, 1, 1, 1, 0, 0, 0>;
```

`rust-mqtt` sizes everything at compile time, so the client type carries its limits as const generics: up to 2 subscriptions in flight, 1 incoming and 1 outgoing publication waiting for acknowledgement, and so on. `AllocBuffer` takes the memory for received packets from the heap. The [`Client` documentation](https://docs.rs/rust-mqtt/0.6.0/rust_mqtt/client/struct.Client.html) explains each parameter.

For more about the MQTT side, see the [Publishing Data to an MQTT Broker](https://docs.espressif.com/projects/rust/no_std-training/application/publishing-data.html) chapter of the training.

## 7. Put it together in `main`

Replace `src/bin/main.rs` with the version for your board. Only the LED pin differs:

{{< tabs group="board" >}}
{{< tab label="S31-CoreBoard" >}}
```rust
#![no_std]
#![no_main]
#![deny(
    clippy::mem_forget,
    reason = "mem::forget is generally not safe to do with esp_hal types, especially those \
    holding buffers for the duration of a data transfer."
)]
#![deny(clippy::large_stack_frames)]

use embassy_executor::Spawner;
use embassy_net::StackResources;
use esp_backtrace as _;
use esp_hal::{clock::CpuClock, rmt::Rmt, rng::Rng, time::Rate, timer::timg::TimerGroup};
use esp_hal_smartled::{RmtSmartLeds, WS2812B_TIMING};
use esp_radio::wifi::{ControllerConfig, Interface, WifiController};
use log::info;
use mqtt_led::{led, mqtt, name, wifi};
use static_cell::StaticCell;
```

In order, `main`:

1. Creates a 72 KiB heap, replacing the one the template generated, because the Wi-Fi driver needs more.
2. Starts the scheduler.
3. Creates the LED driver in async mode (`into_async()`), and starts `led_task` with it.
4. Creates the Wi-Fi controller with the station configuration from `wifi.rs`, and the station interface.
5. Creates the network stack with DHCP. `StackResources<3>` has room for three sockets: DHCP, DNS, and the MQTT connection. The resources must live forever, and a [`StaticCell`](https://docs.rs/static_cell) gives you that safely: you fill it once at run time and get a `&'static mut` back. For details, see [Why the Stack Resources Are Static](https://docs.espressif.com/projects/rust/no_std-training/application/wifi-connectivity.html#why-the-stack-resources-are-static).
6. Makes the board's name, also in a `StaticCell`, because the MQTT task keeps it forever.
7. Starts the Wi-Fi, network, and MQTT tasks. From then on everything happens in the tasks, so `main` waits forever with `core::future::pending()`.

### 9.2 Paint the room with BOOT

When you press **BOOT**, send a random color to every board in the room.

Hints:

- Start a button task in `main`, like the one in the ESP-NOW assignment's `main.rs`, and let it signal a new `static BOOT_PRESSED: Signal<CriticalSectionRawMutex, ()>` in `mqtt.rs`. On the ESP32-C3-LCDkit, BOOT is the rotary encoder knob.
- In the session loop, `select3` from `embassy-futures` waits for three futures instead of two.
- `esp_hal::rng::Rng::new().random()` gives you a random `u32`.
- Publish to `all_set_topic` **without** `retain()`. Otherwise every board that joins later would take that color too.

<details><summary>Show the solution</summary>

In `src/mqtt.rs`, add the signal next to the imports:

```rust
use embassy_futures::select::{Either3, select3};
use embassy_sync::{blocking_mutex::raw::CriticalSectionRawMutex, signal::Signal};

/// Signaled by the button task when BOOT is pressed.
pub static BOOT_PRESSED: Signal<CriticalSectionRawMutex, ()> = Signal::new();
```

Wait for it in the session loop:

```rust
        let header = match select3(
            client.poll_header(),
            Timer::after(PING_INTERVAL),
            BOOT_PRESSED.wait(),
        )
        .await
        {
            Either3::First(header) => header.map_err(|_| "connection lost")?,
            Either3::Second(()) => {
                client.ping().await.map_err(|_| "ping failed")?;
                continue;
            }
            Either3::Third(()) => {
                let random = esp_hal::rng::Rng::new().random();
                let color = RGB8::new((random >> 16) as u8, (random >> 8) as u8, random as u8);
                let text = format_color(color);
                info!("MQTT: BOOT pressed, sending {text} to the room");
                // Not retained: a board that joins later shouldn't get it.
                publish_to(&mut client, &all_set_topic, &text, false).await?;
                continue;
            }
        };
```

And let `publish()` call a version that can publish without `retain()`:

```rust
/// Publishes a retained message, so the web page sees it even if it connects later.
async fn publish(
    client: &mut MqttClient<'_, '_>,
    topic: &str,
    payload: &str,
) -> Result<(), &'static str> {
    publish_to(client, topic, payload, true).await
}

/// Publishes a message, retained or not.
async fn publish_to(
    client: &mut MqttClient<'_, '_>,
    topic: &str,
    payload: &str,
    retain: bool,
) -> Result<(), &'static str> {
    let topic = TopicName::new(MqttString::try_from(topic).unwrap()).unwrap();
    let mut options = PublicationOptions::new(TopicReference::Name(topic));
    if retain {
        options = options.retain();
    }
    client
        .publish(&options, Bytes::from(payload.as_bytes()))
        .await
        .map_err(|_| "publish failed")?;
    Ok(())
}
```

```rust
/// Tells the MQTT task when BOOT is pressed. BOOT pulls the pin low.
#[embassy_executor::task]
async fn button_task(pin: AnyPin<'static>) {
    let mut button = Input::new(pin, InputConfig::default().with_pull(Pull::Up));
    loop {
        button.wait_for_falling_edge().await;
        mqtt::BOOT_PRESSED.signal(());
        // Ignore the bounces, then wait for the release.
        Timer::after(Duration::from_millis(50)).await;
        button.wait_for_high().await;
    }
}
```

```rust
//! The onboard RGB LED, owned by one task. Other tasks send it new colors.

use embassy_sync::{blocking_mutex::raw::CriticalSectionRawMutex, signal::Signal};

use esp_hal_smartled::{RmtSmartLeds, buffer_size, color_order};

/// The LED driver: one WS2812 LED, async RMT channel.

/// The newest color for the LED. A `Signal` keeps only the latest value, so a
/// burst of colors from the web page never queues up.

/// Waits for colors and writes each one to the LED.

    loop {
        let color = LED_COLOR.wait().await;
        // Gamma correction makes the LED look like the color picked on the web page.
        if let Err(e) = led.write(gamma([color].into_iter())).await {
            warn!("LED write failed: {e:?}");
        }
    }
}
```

```rust
//! MQTT: joins a room on the broker and lets the web page set the LED color.
//!
//! Topics, below `esp-hal-workshop/<room>/<board name>/`:
//!
//! | Topic    | Direction       | Payload                | Retained |
//! |----------|-----------------|------------------------|----------|
//! | `status` | board -> page   | `online` / `offline`   | yes      |
//! | `color`  | board -> page   | the LED color, `#rrggbb` | yes    |
//! | `set`    | page -> board   | a new color, `#rrggbb` | no       |
//!
//! The board also listens on `esp-hal-workshop/<room>/all/set`, which sets
//! every board in the room at once.

use core::{fmt::Write, num::NonZero};

use embassy_futures::select::{Either, select};
use embassy_net::{IpAddress, Stack, dns::DnsQueryType, tcp::TcpSocket};
use embassy_time::{Duration, Timer};
use log::{info, warn};
use rust_mqtt::{
    Bytes,
    buffer::AllocBuffer,
    client::{
        Client,
        event::Event,
        options::{
            ConnectOptions, PublicationOptions, SubscriptionOptions, TopicReference, WillOptions,
        },
    },
    config::KeepAlive,
    types::{MqttBinary, MqttString, TopicFilter, TopicName},
};
use smart_leds::RGB8;

use crate::led::LED_COLOR;

/// The broker, compiled in from `MQTT_HOST` and `MQTT_PORT` (optional).
const MQTT_HOST: &str = match option_env!("MQTT_HOST") {
    Some(host) => host,
    None => "broker.hivemq.com",
};
const MQTT_PORT: &str = match option_env!("MQTT_PORT") {
    Some(port) => port,
    None => "1883",
};
/// The room to join, compiled in from `ROOM` (optional).
pub const ROOM: &str = match option_env!("ROOM") {
    Some(room) => room,
    None => "lobby",
};
/// Every topic of this workshop starts with this.
const PREFIX: &str = "esp-hal-workshop";

/// How often the board pings the broker, so it knows the board is still there.
const PING_INTERVAL: Duration = Duration::from_secs(30);

type Topic = heapless::String<96>;

fn topic(name: &str, leaf: &str) -> Topic {
    let mut topic = Topic::new();
    write!(topic, "{PREFIX}/{ROOM}/{name}/{leaf}").expect("topic fits");
    topic
}

/// `#rrggbb` (or `rrggbb`) to a color.
fn parse_color(text: &[u8]) -> Option<RGB8> {
    let text = core::str::from_utf8(text).ok()?.trim();
    let hex = text.strip_prefix('#').unwrap_or(text);
    if hex.len() != 6 {
        return None;
    }
    let value = u32::from_str_radix(hex, 16).ok()?;
    Some(RGB8::new(
        (value >> 16) as u8,
        (value >> 8) as u8,
        value as u8,
    ))
}

fn format_color(color: RGB8) -> heapless::String<7> {
    let mut text = heapless::String::new();
    write!(text, "#{:02x}{:02x}{:02x}", color.r, color.g, color.b).expect("7 characters fit");
    text
}

/// Connects to the broker, and connects again whenever something fails.
#[embassy_executor::task]
pub async fn mqtt_task(stack: Stack<'static>, name: &'static str) {
    let mut rx_buffer = [0u8; 2048];
    let mut tx_buffer = [0u8; 2048];
    let mut color = RGB8::default();

    loop {
        stack.wait_config_up().await;
        if let Some(config) = stack.config_v4() {
            info!("Got IP address {}", config.address);
        }
        if let Err(e) = session(stack, name, &mut rx_buffer, &mut tx_buffer, &mut color).await {
            warn!("MQTT: {e}, reconnecting in 5 s");
        }
        Timer::after(Duration::from_secs(5)).await;
    }
}

/// One connection to the broker. Returns only when something fails.
async fn session(
    stack: Stack<'static>,
    name: &str,
    rx_buffer: &mut [u8],
    tx_buffer: &mut [u8],
    color: &mut RGB8,
) -> Result<(), &'static str> {
    // 1. Find the broker's IP address.
    let address = match MQTT_HOST.parse::<core::net::Ipv4Addr>() {
        Ok(ip) => IpAddress::Ipv4(ip),
        Err(_) => *stack
            .dns_query(MQTT_HOST, DnsQueryType::A)
            .await
            .map_err(|_| "DNS lookup failed")?
            .first()
            .ok_or("no address for the broker")?,
    };
    let port: u16 = MQTT_PORT.parse().map_err(|_| "MQTT_PORT is not a number")?;

    // 2. Open a TCP connection.
    let mut socket = TcpSocket::new(stack, rx_buffer, tx_buffer);
    socket.set_timeout(Some(Duration::from_secs(90)));
    info!("MQTT: connecting to {MQTT_HOST}:{port}...");
    socket
        .connect((address, port))
        .await
        .map_err(|_| "TCP connection failed")?;

    // 3. Connect MQTT. If the board disappears, the broker publishes the will:
    //    `offline` on our status topic.
    let status_topic = topic(name, "status");
    let color_topic = topic(name, "color");
    let set_topic = topic(name, "set");
    let all_set_topic = topic("all", "set");

    let mut client_id = heapless::String::<32>::new();
    write!(client_id, "esp-hal-{name}").expect("client ID fits");

    let mut buffer = AllocBuffer;
    let mut client = MqttClient::new(&mut buffer);
    let will = WillOptions::new(
        TopicName::new(MqttString::try_from(status_topic.as_str()).unwrap()).unwrap(),
        MqttBinary::try_from("offline").unwrap(),
    )
    .retain();
    let options = ConnectOptions::new()
        .clean_start()
        .keep_alive(KeepAlive::Seconds(NonZero::new(60).unwrap()))
        .will(will);
    client
        .connect(
            socket,
            &options,
            Some(MqttString::try_from(client_id.as_str()).unwrap()),
        )
        .await
        .map_err(|_| "MQTT connection refused")?;
    info!("MQTT: connected, room '{ROOM}', board '{name}'");

    // 4. Tell the room we are here, and which color we show.
    publish(&mut client, &status_topic, "online").await?;
    publish(&mut client, &color_topic, &format_color(*color)).await?;

    // 5. Listen for new colors.
    for filter in [&set_topic, &all_set_topic] {
        let filter = TopicFilter::new(MqttString::try_from(filter.as_str()).unwrap()).unwrap();
        client
            .subscribe(filter, &SubscriptionOptions::new())
            .await
            .map_err(|_| "subscribe failed")?;
    }

    // 6. Wait for messages; ping the broker when it's quiet.
    loop {
        let header = match select(client.poll_header(), Timer::after(PING_INTERVAL)).await {
            Either::First(header) => header.map_err(|_| "connection lost")?,
            Either::Second(()) => {
                client.ping().await.map_err(|_| "ping failed")?;
                continue;
            }
        };
        let event = client
            .poll_body(header)
            .await
            .map_err(|_| "connection lost")?;
        let Event::Publish(publish_event) = event else {
            continue;
        };
        match parse_color(&publish_event.message) {
            Some(new_color) => {
                *color = new_color;
                LED_COLOR.signal(new_color);
                let text = format_color(new_color);
                info!("MQTT: LED set to {text}");
                publish(&mut client, &color_topic, &text).await?;
            }
            None => warn!("MQTT: ignored a message that is not a #rrggbb color"),
        }
    }
}

/// The MQTT client type: a TCP socket underneath, buffers from the heap, and
/// small limits on how many requests may be in flight at once.
type MqttClient<'a, 's> = Client<'a, 's, TcpSocket<'s>, AllocBuffer, 2, 1, 1, 1, 0, 0, 0>;

/// Publishes a retained message, so the web page sees it even if it connects later.
async fn publish(
    client: &mut MqttClient<'_, '_>,
    topic: &str,
    payload: &str,
) -> Result<(), &'static str> {
    let topic = TopicName::new(MqttString::try_from(topic).unwrap()).unwrap();
    let options = PublicationOptions::new(TopicReference::Name(topic)).retain();
    client
        .publish(&options, Bytes::from(payload.as_bytes()))
        .await
        .map_err(|_| "publish failed")?;
    Ok(())
}
```
